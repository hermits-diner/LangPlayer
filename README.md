# LangPlayer

의미 단위(문장) 자막을 클릭하면 그 구간만 반복 재생되고, 그 자리에서 받아쓰기를 채점받는 외국어 학습 플레이어.

설치 없이 브라우저에서 동작하며, **로컬 파일은 어디에도 업로드되지 않는다** (전부 브라우저 안에서 처리).

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 단위 테스트
npm run build    # 타입체크 + 프로덕션 빌드
```

## 사용법

영상/오디오 파일과 자막 파일을 **함께 끌어다 놓으면** 자동으로 짝지어진다. YouTube는 주소를 붙여넣은 뒤 자막 파일을 따로 올린다.

### 재생·이동

| 키 | 동작 |
|---|---|
| `F5` / `Space` | 현재 구간 반복 재생 |
| `F6` | 일시정지 — 멈춘 상태에서 다시 누르면 3초 되감아 재생 |
| `F7` / `F8` | 앞 / 뒤 문장 |
| `Ctrl+F7` / `Ctrl+F8` | 첫 / 끝 문장 |
| `F11` | 연속 재생 (선택 구간, 없으면 현재 문장부터 끝까지) |
| `↑` `↓` | 앞 / 뒤 문장 (입력 중이 아닐 때) |

### 받아쓰기

| 키 | 동작 |
|---|---|
| `Enter` | 채점 → 다시 누르면 다음 문장 |
| `Tab` | 자막 정답 보기 토글 |
| `Esc` | 현재 문장 다시 듣기 |

Enter가 상황에 따라 다르게 동작하는 것이 핵심이다. 채점 전이면 채점하고, 채점 결과를 보고 있으면 다음 문장으로 넘어간다. 받아쓰기 → 확인 → 다음이 한 손가락으로 이어진다.

### 섹션 편집·선택

| 조작 | 동작 |
|---|---|
| `F3` | 섹션 합치기 (범위를 골랐으면 통째로) |
| `F4` / `Ctrl+오른쪽 클릭` | 섹션 나누기 |
| `Ctrl+G` / `Ctrl+Shift+G` | 뒤 문장 하나씩 / 전체를 임시로 묶기 — `Enter`로 해제 |
| 오른쪽 클릭 | 개별 선택 토글 |
| `Shift`+클릭, 음파창 드래그 | 범위 선택 |

### 음파창·기타

| 키 | 동작 |
|---|---|
| 숫자패드 `+` `-` | 확대 / 축소 (`Ctrl`+휠도 동작) |
| 숫자패드 `*` `/` | 선택 구간 맞춤 / 전체 보기 |
| `Ctrl+↑` `Ctrl+↓` | 음량 |
| `Ctrl+←/→` | 자막 싱크 ±0.1초 |
| `1`~`9` | 반복 횟수 |
| `[` `]` | 배속 |

`F5`는 브라우저 새로고침을 가로챈다 — 새로고침은 `Ctrl+R`을 쓴다. 시스템 음량은 브라우저가 제어할 수 없어 플레이어 음량으로 동작한다.

## 음파창

자동 맞춤이 쓰는 에너지 포락선을 그대로 그린다. 원본 샘플(수천만 개)이 아니라 10 ms로 압축된 값이라 2시간짜리도 72만 칸이면 끝나서, 매 프레임 다시 그려도 가볍다. 디코딩은 파형과 자동 맞춤이 한 번만 하고 나눠 쓴다.

- **드래그**: 그 구간만 한 번 재생 (반복 횟수·패딩 무시)
- **오른쪽 클릭**: 재생 / 정지
- **`Ctrl`+오른쪽 클릭**: 그 지점에서 문장 나누기

**섹션을 편집하면 재생 구간도 함께 따라간다.** 재생 중이던 루프는 편집 전 시각을 붙들고 있어서, 그대로 두면 자막은 합쳐졌는데 소리는 옛 경계에서 끊긴다. 합치거나 나눈 직후 새 경계로 루프를 다시 걸어, 결과를 귀로 바로 확인하게 한다.

재생 위치에서 문장을 나눌 때 텍스트는 시간 비율에 맞춰 단어 경계로 가른다. 어디서 끊을지 알 방법이 없지만, 양쪽에 전체 문장을 복제해 두는 것보다는 쓸모 있다. 가장자리 0.5초 안쪽에서는 나누지 않고 원래 자막 큐 경계로 되돌린다 — 문장을 막 고른 직후에는 재생 위치가 첫머리에 붙어 있어서, 그대로 나누면 부스러기만 생긴다.

## 자막 싱크 자동 맞춤

인터넷에서 받은 자막은 십중팔구 어긋나 있다. `자동 맞춤` 버튼 하나로 잡는다.

**원리** — 오디오를 8 kHz 모노로 디코딩해 10 ms 단위 에너지 포락선을 만들고, 임계값을 씌워 "말함/침묵" 이진 신호를 얻는다. 자막도 같은 이진 신호로 바꿔 FFT 상호상관을 돌리면 겹침이 최대가 되는 지연이 곧 오프셋이다. **자막의 언어도 내용도 볼 필요가 없다** — 소리가 나는 리듬만 맞추면 되기 때문이다.

**어긋남의 두 종류를 모두 잡는다.**

| 유형 | 원인 | 해법 |
|---|---|---|
| 상수 오프셋 | 다른 릴리즈(인트로 유무) | 통째로 이동 |
| 선형 드리프트 | 프레임레이트 불일치 (23.976 ↔ 25fps) | 배율 + 이동 |

드리프트는 4.3%씩 벌어져 2시간이면 끝에서 5분 넘게 어긋난다. 초반만 맞추고 끝에서 좌절하는 흔한 경우다. 중요한 점은 **드리프트 배율이 임의의 값이 아니라 표준 프레임레이트 사이의 비율로만 생긴다**는 것이다. 그래서 기울기를 연속적으로 추정하지 않고 후보 배율(25/24, 25/23.976 …)을 하나씩 대입해 가장 잘 맞는 것을 고른다 — 훨씬 안정적이고, 정답이 곧 실제 원인과 일치한다.

**신뢰도**는 상관값의 절대 크기가 아니라 **최고 봉우리 ÷ 차선 봉우리**로 잰다. 실제 오디오는 음악·효과음 때문에 정답이어도 상관값이 0.5 언저리라 절대 크기는 못 믿는다. 반면 "정답이 차선책보다 얼마나 앞서는가"는 잘 구분된다. 신뢰도가 낮으면 조용히 틀린 값을 적용하지 않고 실패를 알린다.

무거운 계산은 Web Worker에서 돌고, 수백 MB짜리 샘플 배열은 전송 가능 객체로 넘겨 복사하지 않는다. 150초 오디오 기준 0.5초.

**탭 맞추기** — 자동 맞춤이 실패했거나 YouTube(오디오 접근 불가)일 때 쓴다. 문장 시작 3초 전부터 들려주고, 소리가 시작되는 순간 버튼을 누르면 그 차이가 곧 오프셋이다. 5초면 끝난다.

## 구조

```
src/core/
  subtitle/   decode(인코딩 감지) → parse(srt·vtt·smi·ass) → segment(문장 병합)
  dictation/  normalize → score(WER 정렬 기반 채점)
  player/     PlayerAdapter ← HtmlMediaAdapter · YouTubeAdapter
  loop/       LoopController (구간 반복 엔진)
  files/      드롭 파일 분류 및 미디어↔자막 매칭
  storage/    IndexedDB(Dexie) 학습 기록
  sync/       오디오 분석 — 포락선(파형) · 자동 맞춤(FFT · VAD · 상호상관) · Web Worker
```

## 학습 기록 (IndexedDB)

같은 파일을 다시 열면 **이전 학습이 그대로 이어진다** — 문장별 받아쓰기 입력, 채점 결과, 마지막 문장 위치, 자막 싱크 보정, 수동으로 고친 문장 경계. 반복 횟수·배속·간격 같은 설정은 전역으로 유지된다.

- **파일 식별**: 브라우저는 파일 경로를 주지 않으므로 `이름:크기:수정시각`을 지문으로 쓴다. 같은 영상에 다른 자막을 물리면 별개 세션으로 다룬다.
- **자막 내용까지 대조한다.** 세션 키는 파일 *이름*으로만 만들어져서, 같은 이름의 다른 자막을 올리면 키가 겹친다. 큐 내용의 해시를 함께 저장해 두고 그것까지 맞을 때만 복원한다 — 그러지 않으면 방금 올린 자막이 옛 기록에 덮여 사라진다.
- **채점 결과는 저장하지 않는다.** 입력 문자열과 "채점 완료" 여부만 남기고 불러올 때 다시 채점한다. 채점이 순수 함수라 결과가 같고, 채점 로직을 고쳐도 기록이 낡지 않으며 용량도 훨씬 작다.
- **기록 키는 문장 id가 아니라 첫 큐의 id.** 문장 경계를 병합/분할해도 이미 입력한 답이 엉뚱한 문장에 붙지 않는다.
- 저장소 접근이 실패해도(시크릿 모드·용량 초과) 학습은 그대로 진행된다. 첫 화면에서 저장된 기록을 지울 수 있다.

### 용량과 삭제 위험

미디어 파일은 저장하지 않고 텍스트만 저장하므로 용량은 사실상 문제가 되지 않는다. 2시간 영화 한 편을 전부 학습해도 **0.5~1 MB** 수준이고, 브라우저 할당량은 보통 수 GB(테스트 환경 기준 10 GB)다.

**실제 위험은 용량이 아니라 자동 삭제다.** IndexedDB의 기본 등급은 `best-effort`라 디스크가 부족하면 브라우저가 예고 없이 지우고, Safari는 일정 기간 방문이 없으면 지운다. 그래서 첫 저장이 성공한 직후 `navigator.storage.persist()`로 삭제 면제 등급을 요청한다 — 페이지 로드 직후가 아니라 **지킬 기록이 실제로 생긴 뒤**에 부르는 것이 맞다 (Firefox는 이때 사용자에게 묻는다).

첫 화면에 현재 사용량과 보관 등급을 표시하고, 등급을 못 받았으면 수동으로 재요청할 수 있다. Chrome은 재방문·북마크 같은 참여도 신호를 보고 프롬프트 없이 자동 승인/거절하므로, 참여도가 낮은 초기에는 거절될 수 있다.

### 설계상 중요한 세 가지

**1. 자막 큐 ≠ 문장.** SRT 큐는 "화면에 한 번에 띄울 분량"으로 잘려 있어 한 문장이 2~3개 큐에 흩어진다. 그대로 반복하면 문장 중간에서 끊긴다. `segment.ts`가 문장 종결 부호를 기준으로 다시 붙이고(약어·이니셜 예외 처리 포함), 문장부호가 없는 자동생성 자막은 길이·쉼 기준으로 자른다. 결과는 UI에서 수동 병합/분할로 교정할 수 있다.

**2. 구간 끝 감지는 폴링으로.** `timeupdate` 이벤트는 초당 4회라 최대 250ms를 넘겨버려 다음 문장이 새어 들어온다. `requestVideoFrameCallback`/`requestAnimationFrame`으로 재생 위치를 폴링한다. 앞뒤 패딩(기본 200ms/300ms)이 없으면 첫 음소가 잘려 받아쓰기가 불가능해진다.

**3. 채점은 O/X가 아니라 정렬.** 편집거리 DP(WER)로 정답과 입력을 정렬하면 삭제/삽입뿐 아니라 **치환**이 나오는데, 이것이 곧 "A를 B로 잘못 들었다"에 해당한다. 오타(편집거리 ≤2)는 청취 오류와 구분해 부분 점수를 준다.

## 텍스트창 (Ctrl+T)

문장별로 오가며 받아쓰던 것을 **한 편의 글로 놓고** 고치는 자리다. 네 가지 문서를 다룬다.

| 문서 | 무엇인가 | 폴더 | 파일명 |
|---|---|---|---|
| 패치 | 정답 스크립트 (자막에서 자동 생성) | `Patches/` | `pap1102-1.txt` |
| 드랩 | 내가 받아쓴 초안 | `Drafts/` | `dap1102-1.txt` |
| 약형드랩 | 패치에서 빈칸을 뚫은 것 | `Gapped Drafts/` | `gap1102-1.txt` |
| 해석 | 우리말 번역 | `Translations/` | `tap1102-1.txt` |

| 키 | 동작 |
|---|---|
| `Ctrl+T` | 텍스트창 열기/닫기 |
| `F2` | 아래창(패치) 열기/닫기 |
| `F12` | 창 크기 (절반 ↔ 전체) |
| `F9` | 비교 모드 — 위창을 패치와 줄마다 대조 |
| `Alt+D` | 패치에서 약형드랩 만들기 |
| `Alt+F7` / `Alt+F8` | 클립보드에서 가져오기 / 내보내기 |
| `Ctrl+O` / `Ctrl+S` | 파일 열기 / 받아쓰기 전문 저장 |

**드랩은 문장별 받아쓰기와 같은 데이터다.** 문장 하나가 정확히 한 줄이라는 규칙을 두어 양쪽이 왕복한다 — 텍스트창에서 3번째 줄을 고치면 3번 문장의 받아쓰기가 바뀐다. 줄이 남으면 마지막 문장에 이어 붙여 쓴 내용을 잃지 않는다.

**약형드랩은 결정적으로 생성된다.** 같은 패치에서는 늘 같은 자리에 빈칸이 뚫려야 복습이 되기 때문이다. 밑줄 개수가 글자 수 단서로 남고, 문장부호는 보존해 문장 구조를 힌트로 준다. 비교 모드는 빈칸(`___`)을 오답이 아니라 "아직 안 채운 자리"로 본다.

**폴더 저장**은 File System Access API로 작업 폴더를 한 번 지정받아 쓴다 (Chrome·Edge). 권한은 다음 방문에도 이어진다. 미지원 브라우저에서는 다운로드/파일 선택으로 대신하되 파일명 규칙은 지켜서, 나중에 폴더를 연결했을 때 그대로 들어맞게 한다.

## 제약

- **재생 가능 여부를 미리 단정하지 않는다.** OS에 코덱이 깔려 있으면 Chrome이 MKV·HEVC를 그냥 재생하기도 한다(실제로 확인했다). 확장자만 보고 막으면 잘 되는 파일을 못 쓰게 되므로, 판단은 실제 재생 결과에 맡기고 실패했을 때만 형식을 짚어 안내한다.
- YouTube 자동 캡션은 긁어오지 않는다 (ToS 회색지대). 자막 파일을 직접 올려야 한다. YouTube는 오디오에 접근할 수 없어 파형과 자동 맞춤도 쓸 수 없다.

## 검증 상태

- 단위 테스트 144개 통과 — 자막 파싱(EUC-KR/BOM/변종 SRT/이중언어 SMI), 세그먼트 병합, 채점, 루프 상태 머신(패딩·반복·취소·무한반복·무음간격), 파일 매칭, 설정 직렬화, FFT 왕복, VAD 레벨 불변성, 오프셋·드리프트 복원, 싱크 보정 합성, 나누기 경계 방어, 문서↔문장 왕복, 약형드랩 결정성, 줄 단위 비교
- 브라우저 확인 완료 — 파일 드롭 → 6개 큐가 4개 문장으로 병합 → 받아쓰기 → 채점 diff(83%, 놓친 단어·잘못 들은 단어 표시) → 키보드 이동/자막 토글
- 학습 기록 확인 완료 — 저장 후 새로고침 → 같은 파일 재투입 시 입력·채점·문장 위치·전역 설정 복원
- 자동 맞춤 확인 완료 — 일부러 +2.5초 어긋낸 자막(150초·45문장)을 **-2.50초, 신뢰도 100%, 0.5초**만에 교정
- 음파창·섹션 조작 확인 완료 — 파형 렌더링(1361×104, 1026개 열), F7/F8/Ctrl+F7/Ctrl+F8 이동, 줌 인·전체·선택맞춤, F3 합치기(45→44) → F4 나누기(→45 정확히 복원), 오른쪽클릭 개별선택·Shift+클릭 범위선택(7개), F11 연속 재생
- **미검증**: 실제 오디오·비디오 재생 중의 구간 반복 정확도. 검증에 쓴 브라우저 환경이 미디어를 전혀 로드하지 못해(WAV·WebM·MP4 모두 `readyState 0`) 실측하지 못했다. 루프 로직 자체는 가상 클럭 단위 테스트로 검증되어 있으나, **실제 미디어로 한 번 확인이 필요하다.**

- 텍스트창 확인 완료 — `Ctrl+T` 열기 → `F2` 아래창(패치 자동 채움) → 드랩 3번째 줄 수정이 3번 문장 받아쓰기에 반영 → `Alt+D` 약형드랩 생성(`spoken` → `______`) → `F9` 비교(1번 100%, 2번 0%에 단어별 diff)

## 남은 것

`F1` 도움말, `F10` 메뉴, `Ctrl+P` 인쇄(자막 스크립트).
