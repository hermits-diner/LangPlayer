# LangPlayer

의미 단위(문장) 자막을 클릭하면 그 구간만 반복 재생되고, 그 자리에서 받아쓰며 정답과 대조하는 외국어 학습 플레이어.

설치 없이 브라우저에서 동작하며, **로컬 파일은 어디에도 업로드되지 않는다** (전부 브라우저 안에서 처리).

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 단위 테스트
npm run build    # 타입체크 + 프로덕션 빌드
```

## 사용법

영상/오디오 파일과 자막 파일을 **함께 끌어다 놓으면** 자동으로 짝지어진다. YouTube는 주소를 붙여넣은 뒤 자막 파일을 따로 올린다.

### 재생·이동

| 키 | 동작 |
|---|---|
| `F5` / `Space` | 현재 구간 반복 재생 |
| `F6` / `F7` | 앞 / 뒤 문장 |
| `Ctrl+F6` / `Ctrl+F7` | 첫 / 끝 문장 |
| `F8` | 일시정지 — 멈춘 상태에서 다시 누르면 3초 되감아 재생 |
| `F11` | 연속 재생 (선택 구간, 없으면 현재 문장부터 끝까지) |
| `↑` `↓` | 앞 / 뒤 문장 (입력 중이 아닐 때) |

### 받아쓰기

| 키 | 동작 |
|---|---|
| `Enter` | 다음 문장 |
| `↑` `↓` | 앞 / 뒤 문장 — 입력창 안에서도 동작한다 |
| `Tab` | 자막 정답 보기 토글 |
| `Esc` | 현재 문장 다시 듣기 |

받아쓰기 칸에는 문장 하나만 담기므로 커서를 위아래로 옮길 일이 없다. 그래서 `↑↓`를 앞뒤 문장 이동에 내준다. 전체 문서를 다루는 텍스트창에서는 커서 이동이 필요하므로 그대로 두고, 대신 커서가 놓인 줄이 현재 문장이 된다.

**Enter는 언제나 '다음 문장'이다.** 다 썼으면 Enter — 그게 전부다. 듣고 쓰는 흐름이 한 손가락으로 끊김 없이 이어진다.

**점수를 매기지 않는다.** `Tab`으로 자막을 열어 스스로 대조한다. 어디서 왜 막혔는지는 본인이 가장 잘 안다 — 기계가 매긴 숫자는 그 판단을 대신해 주지 못하면서 점수에만 신경 쓰게 만든다.

### 섹션 편집·선택

| 조작 | 동작 |
|---|---|
| `F3` | 섹션 합치기 (범위를 골랐으면 통째로) |
| `F4` / `Ctrl+오른쪽 클릭` | 섹션 나누기 |
| 문장 두 번 클릭 | **자막 문장 고치기** |
| 오른쪽 클릭 | 개별 선택 토글 |
| `Shift`+클릭, 음파창 드래그 | 범위 선택 |

**자막이 틀렸으면 그 자리에서 고친다.** 자동생성 자막에는 오타가 흔하고, 재생 위치로 나눌 때 글자 수 비율로 가른 텍스트도 어긋난다. 정답을 눈으로 대조하는 도구이므로 정답이 틀려 있으면 곤란하다. 문장을 두 번 클릭하거나 `고치기` 버튼을 누르면 그 자리에서 편집되고, 텍스트창 아래창(`F2`)에서는 자막 전체를 한 화면에서 훑어 고칠 수 있다. 고친 자막은 학습 기록에 함께 저장된다.

### 음파창·기타

| 키 | 동작 |
|---|---|
| 숫자패드 `+` `-` | 확대 / 축소 (`Ctrl`+휠도 동작) |
| 숫자패드 `/` | 전체 보기 |
| `Ctrl+↑` `Ctrl+↓` | 음량 |
| `Ctrl+←/→` | 자막 싱크 ±0.1초 |
| `1`~`9` | 반복 횟수 |
| `[` `]` | 배속 |

`F5`는 브라우저 새로고침을 가로챈다 — 새로고침은 `Ctrl+R`을 쓴다. 시스템 음량은 브라우저가 제어할 수 없어 플레이어 음량으로 동작한다.

## 음파창

자동 맞춤이 쓰는 에너지 포락선을 그대로 그린다. 원본 샘플(수천만 개)이 아니라 10 ms로 압축된 값이라 2시간짜리도 72만 칸이면 끝나서, 매 프레임 다시 그려도 가볍다. 디코딩은 파형과 자동 맞춤이 한 번만 하고 나눠 쓴다.

- **드래그**: 그 구간만 한 번 재생 (반복 횟수·패딩 무시)
- **오른쪽 클릭**: 재생 / 정지
- **`Ctrl`+오른쪽 클릭**: 그 지점에서 문장 나누기

**섹션을 편집하면 재생 구간도 함께 따라간다.** 재생 중이던 루프는 편집 전 시각을 붙들고 있어서, 그대로 두면 자막은 합쳐졌는데 소리는 옛 경계에서 끊긴다. 합치거나 나눈 직후 새 경계로 루프를 다시 걸어, 결과를 귀로 바로 확인하게 한다.

### 쪼개기는 문장 단위가 기본

`F4`는 세 가지 기준을 차례로 시도한다.

1. **문장 단위** — 구간에 문장이 여럿이면 문장별로 가른다 (이 앱의 학습 단위가 문장이므로 기본값)
2. **재생 위치** — 문장이 하나뿐인데 사용자가 어딘가를 짚어 뒀다면 거기서
3. **큐 경계** — 둘 다 아니면 원래 자막이 나눠 둔 대로 되돌린다

문장 단위로 가를 때 어려운 쪽은 텍스트가 아니라 **시각**이다. 자막에는 문장이 어디서 끝나는지 시간 정보가 없다. 그래서 글자 수 비율로 자리를 어림한 뒤, 더 믿을 만한 단서로 당겨 붙인다 — **원래 큐 경계**(자막 파일이 준 값이라 사실상 정답)가 첫째고, 없으면 **파형에서 가장 조용한 지점**(문장 사이에는 숨이 있다)이다. 어림값의 오차는 구간이 길수록 커지므로 큐 경계를 찾는 범위도 길이에 비례해 넓힌다.

문장 경계 판정은 종결 부호를 보되, **다음 단어가 소문자로 시작하면 아직 끝나지 않은 것으로 본다**. `"Go away!" she said.`는 한 문장이다. 합치기도 같은 규칙을 쓴다.

재생 위치에서 문장을 나눌 때 텍스트는 시간 비율에 맞춰 단어 경계로 가른다. 어디서 끊을지 알 방법이 없지만, 양쪽에 전체 문장을 복제해 두는 것보다는 쓸모 있다. 가장자리 0.5초 안쪽에서는 나누지 않고 원래 자막 큐 경계로 되돌린다 — 문장을 막 고른 직후에는 재생 위치가 첫머리에 붙어 있어서, 그대로 나누면 부스러기만 생긴다.

## 자막 싱크 자동 맞춤

인터넷에서 받은 자막은 십중팔구 어긋나 있다. `자동 맞춤` 버튼 하나로 잡는다.

**원리** — 오디오를 8 kHz 모노로 디코딩해 10 ms 단위 에너지 포락선을 만들고, 임계값을 씌워 "말함/침묵" 이진 신호를 얻는다. 자막도 같은 이진 신호로 바꿔 FFT 상호상관을 돌리면 겹침이 최대가 되는 지연이 곧 오프셋이다. **자막의 언어도 내용도 볼 필요가 없다** — 소리가 나는 리듬만 맞추면 되기 때문이다.

**어긋남의 두 종류를 모두 잡는다.**

| 유형 | 원인 | 해법 |
|---|---|---|
| 상수 오프셋 | 다른 릴리즈(인트로 유무) | 통째로 이동 |
| 선형 드리프트 | 프레임레이트 불일치 (23.976 ↔ 25fps) | 배율 + 이동 |

드리프트는 4.3%씩 벌어져 2시간이면 끝에서 5분 넘게 어긋난다. 초반만 맞추고 끝에서 좌절하는 흔한 경우다. 중요한 점은 **드리프트 배율이 임의의 값이 아니라 표준 프레임레이트 사이의 비율로만 생긴다**는 것이다. 그래서 기울기를 연속적으로 추정하지 않고 후보 배율(25/24, 25/23.976 …)을 하나씩 대입해 가장 잘 맞는 것을 고른다 — 훨씬 안정적이고, 정답이 곧 실제 원인과 일치한다.

**신뢰도**는 상관값의 절대 크기가 아니라 **최고 봉우리 ÷ 차선 봉우리**로 잰다. 실제 오디오는 음악·효과음 때문에 정답이어도 상관값이 0.5 언저리라 절대 크기는 못 믿는다. 반면 "정답이 차선책보다 얼마나 앞서는가"는 잘 구분된다. 신뢰도가 낮으면 조용히 틀린 값을 적용하지 않고 실패를 알린다.

무거운 계산은 Web Worker에서 돌고, 수백 MB짜리 샘플 배열은 전송 가능 객체로 넘겨 복사하지 않는다. 150초 오디오 기준 0.5초.

**탭 맞추기** — 자동 맞춤이 실패했거나 YouTube(오디오 접근 불가)일 때 쓴다. 문장 시작 3초 전부터 들려주고, 소리가 시작되는 순간 버튼을 누르면 그 차이가 곧 오프셋이다. 5초면 끝난다.

### 문장별 맞춤

자동 맞춤은 자막 **전체**에 변환 하나를 걸어 평균적으로 가장 잘 맞는 자리를 찾는다. 그런데 자막 제작 품질이 고르지 않으면 문장마다 조금씩 이르거나 늦는다 — 전체를 아무리 잘 밀어도 각 문장은 어긋난 채로 남는다. 전체 변환으로는 닿지 않는 종류의 어긋남이다.

파형에는 소리가 **시작하고 끝나는 지점**이 이미 다 들어 있다. `문장별 맞춤`은 각 문장의 시작을 가장 가까운 소리 시작점으로, 끝을 가장 가까운 소리 끝점으로 당긴다 (기본 ±0.6초 안).

- 성대 진동 사이의 순간적인 골까지 경계로 세면 한 문장 안에 가짜 시작점이 수십 개 생긴다. 80 ms보다 짧은 조각은 무시한다.
- 창 안에 마땅한 경계가 없으면 **손대지 않는다.** 어림짐작으로 옮기지 않는다.
- 앞뒤 문장이 겹치거나 순서가 뒤집히지 않게 앞에서부터 차례로 처리한다.
- 수백 문장을 한꺼번에 옮기므로 **한 단계 되돌리기**(`↺`)를 함께 준다. 되돌릴 수 없으면 무서워서 못 누른다.

검증: 45문장 자막의 각 줄을 ±0.4초씩 제각각 흔들어 놓고 맞춤을 돌린 결과, **45문장 전부 원본 시각으로 복원**됐다.

## 구조

```
src/core/
  subtitle/   decode(인코딩 감지) → parse(srt·vtt·smi) → segment(문장 병합)
  text/       문장별 입력 ↔ 한 문서 변환
  player/     PlayerAdapter ← HtmlMediaAdapter · YouTubeAdapter
  loop/       LoopController (구간 반복 엔진)
  files/      드롭 파일 분류 및 미디어↔자막 매칭
  storage/    IndexedDB(Dexie) 학습 기록
  sync/       오디오 분석 — 포락선(파형) · 자동 맞춤(FFT · VAD · 상호상관) · Web Worker
```

## 학습 기록 (IndexedDB)

같은 파일을 다시 열면 **이전 학습이 그대로 이어진다** — 문장별 받아쓰기 입력, 마지막 문장 위치, 자막 싱크 보정, 수동으로 고친 문장 경계와 자막 문장. 반복 횟수·배속·간격 같은 설정은 전역으로 유지된다.

- **파일 식별**: 브라우저는 파일 경로를 주지 않으므로 `이름:크기:수정시각`을 지문으로 쓴다. 같은 영상에 다른 자막을 물리면 별개 세션으로 다룬다.
- **자막 내용까지 대조한다.** 세션 키는 파일 *이름*으로만 만들어져서, 같은 이름의 다른 자막을 올리면 키가 겹친다. 큐 내용의 해시를 함께 저장해 두고 그것까지 맞을 때만 복원한다 — 그러지 않으면 방금 올린 자막이 옛 기록에 덮여 사라진다.
- **기록 키는 문장 id가 아니라 첫 큐의 id.** 문장 경계를 병합/분할해도 이미 입력한 답이 엉뚱한 문장에 붙지 않는다.
- 저장소 접근이 실패해도(시크릿 모드·용량 초과) 학습은 그대로 진행된다. 첫 화면에서 저장된 기록을 지울 수 있다.

### 용량과 삭제 위험

미디어 파일은 저장하지 않고 텍스트만 저장하므로 용량은 사실상 문제가 되지 않는다. 2시간 영화 한 편을 전부 학습해도 **0.5~1 MB** 수준이고, 브라우저 할당량은 보통 수 GB(테스트 환경 기준 10 GB)다.

**실제 위험은 용량이 아니라 자동 삭제다.** IndexedDB의 기본 등급은 `best-effort`라 디스크가 부족하면 브라우저가 예고 없이 지우고, Safari는 일정 기간 방문이 없으면 지운다. 그래서 첫 저장이 성공한 직후 `navigator.storage.persist()`로 삭제 면제 등급을 요청한다 — 페이지 로드 직후가 아니라 **지킬 기록이 실제로 생긴 뒤**에 부르는 것이 맞다 (Firefox는 이때 사용자에게 묻는다).

등급을 못 받았을 때만 첫 화면에 경고와 재요청 버튼을 띄운다. 남은 용량 숫자는 보여주지 않는다 — 사용자가 그 숫자를 보고 할 일이 없기 때문이다. Chrome은 재방문·북마크 같은 참여도 신호를 보고 프롬프트 없이 자동 승인/거절하므로, 참여도가 낮은 초기에는 거절될 수 있다.

### 설계상 중요한 두 가지

**1. 자막 큐 ≠ 문장.** SRT 큐는 "화면에 한 번에 띄울 분량"으로 잘려 있어 한 문장이 2~3개 큐에 흩어진다. 그대로 반복하면 문장 중간에서 끊긴다. `segment.ts`가 문장 종결 부호를 기준으로 다시 붙이고(약어·이니셜 예외 처리 포함), 문장부호가 없는 자동생성 자막은 길이·쉼 기준으로 자른다. 결과는 UI에서 수동 병합/분할로 교정할 수 있다.

**2. 구간 끝 감지는 폴링으로.** `timeupdate` 이벤트는 초당 4회라 최대 250ms를 넘겨버려 다음 문장이 새어 들어온다. `requestVideoFrameCallback`/`requestAnimationFrame`으로 재생 위치를 폴링한다. 앞뒤 패딩(기본 200ms/300ms)이 없으면 첫 음소가 잘려 받아쓰기가 불가능해진다.


## 텍스트창 (Ctrl+T)

문장별로 오가며 받아쓰던 것을 **한 편의 글로 놓고** 고치는 자리다. 위창은 내 받아쓰기 전문, 아래창은 자막 원문이다.

| 키 | 동작 |
|---|---|
| `Ctrl+T` | 텍스트창 열기/닫기 |
| `F2` | 자막 원문 보기 |
| `F12` | 창 크기 (절반 ↔ 전체) |
| `Ctrl+O` / `Ctrl+S` | 파일 열기 / 받아쓰기 전문 저장 |

### 도움말 · 메뉴 · 인쇄

| 키 | 동작 |
|---|---|
| `F1` | 단축키 도움말 (전체 목록) |
| `F10` | 메뉴 — 단축키를 모르는 사람도 모든 기능에 닿을 수 있게 |
| `Ctrl+P` | 자막 스크립트 인쇄 |

인쇄는 화면을 그대로 뽑지 않는다. 화면과 종이는 요구가 정반대다 — 어두운 배경을 그대로 뽑으면 잉크만 버리고 읽기도 나쁘다. 화면용 껍데기를 통째로 숨기고 시각 + 문장만 담은 밝은 문서로 다시 짠다. 문장이 페이지 사이에 걸쳐 잘리지 않게 `break-inside: avoid`를 건다.

**두 창 모두 따로 보관하지 않는다.** 위창은 문장별 받아쓰기를 이어 붙인 것이고 아래창은 자막을 이어 붙인 것이라, 그때그때 만들어진다. 사본을 두면 어느 쪽이 진짜인지 헷갈릴 뿐이다.

**텍스트창의 글은 문장별 받아쓰기와 같은 데이터다.** 문장 하나가 정확히 한 줄이라는 규칙을 두어 양쪽이 왕복한다 — 텍스트창에서 3번째 줄을 고치면 3번 문장의 받아쓰기가 바뀐다. 줄이 남으면 마지막 문장에 이어 붙여 쓴 내용을 잃지 않는다.

**커서가 놓인 줄이 곧 현재 문장이다.** 한 줄을 다 쓰고 `Enter`를 누르면 다음 줄로 내려가면서 그 문장이 재생되고, 마우스로 다른 줄을 짚으면 그 문장으로 옮겨간다. 전체 스크립트를 한 문서로 써 내려가면서도 듣기가 따라오게 하기 위해서다.

## 제약

- **재생 가능 여부를 미리 단정하지 않는다.** OS에 코덱이 깔려 있으면 Chrome이 MKV·HEVC를 그냥 재생하기도 한다(실제로 확인했다). 확장자만 보고 막으면 잘 되는 파일을 못 쓰게 되므로, 판단은 실제 재생 결과에 맡기고 실패했을 때만 형식을 짚어 안내한다.
- YouTube는 오디오에 접근할 수 없어 파형과 자동 맞춤을 쓸 수 없다 (iframe 교차 출처). 탭 맞추기로 대신한다.

## YouTube 자막

**자동으로 가져오는 것은 불가능하다.** IFrame Player API는 재생 제어만 내주고 자막 텍스트를 주지 않으며, `api/timedtext` 엔드포인트는 CORS로 막혀 있다. 공식 Data API의 `captions.download`는 **자기가 올린 영상만** 받을 수 있어 학습 용도에는 해당이 없다. 서버로 우회하는 방법은 ToS 위반 소지가 있고 서버 비용도 생긴다.

대신 **'스크립트 표시'에서 복사해 붙여넣는다.** 사용자가 화면에서 직접 복사하는 것은 아무 문제가 없고, 복사 한 번이면 파일로 받은 자막과 완전히 똑같이 흘러간다.

1. 영상 설명란의 `···` → `스크립트 표시`
2. 스크립트 전체 선택 후 복사
3. 오른쪽 사이드바의 붙여넣기 칸에 붙여넣기 (붙이는 즉시 처리된다)

유튜브 스크립트는 시작 시각만 있고 종료 시각이 없다 — SMI와 같은 구조라 다음 항목의 시작을 앞 항목의 끝으로 삼는다. `0:15` / `1:02:03` 양쪽 형식과, 시각과 문장이 한 줄에 붙은 변형도 받는다. 형식은 내용을 보고 판별하므로 SRT·VTT를 붙여넣어도 그대로 동작한다.

## 검증 상태

- 단위 테스트 162개 통과 — 자막 파싱(EUC-KR/BOM/변종 SRT/이중언어 SMI/YouTube 스크립트), 세그먼트 병합, 문장 단위 쪼개기, 루프 상태 머신(패딩·반복·취소·무한반복·무음간격), 파일 매칭, 설정 직렬화, FFT 왕복, VAD 레벨 불변성, 오프셋·드리프트 복원, 문장별 소리 경계 맞춤, 싱크 보정 합성, 문서↔문장 왕복
- 브라우저 확인 완료 — 파일 드롭 → 6개 큐가 4개 문장으로 병합 → 받아쓰기 → Tab 정답 대조 → 키보드 이동
- 학습 기록 확인 완료 — 저장 후 새로고침 → 같은 파일 재투입 시 입력·문장 위치·전역 설정 복원
- 자동 맞춤 확인 완료 — 일부러 +2.5초 어긋낸 자막(150초·45문장)을 **-2.50초, 신뢰도 100%, 0.5초**만에 교정
- 음파창·섹션 조작 확인 완료 — 파형 렌더링(1361×104, 1026개 열), F7/F8/Ctrl+F7/Ctrl+F8 이동, 줌 인·전체·선택맞춤, F3 합치기(45→44) → F4 나누기(→45 정확히 복원), 오른쪽클릭 개별선택·Shift+클릭 범위선택(7개), F11 연속 재생
- **미검증**: 실제 오디오·비디오 재생 중의 구간 반복 정확도. 검증에 쓴 브라우저 환경이 미디어를 전혀 로드하지 못해(WAV·WebM·MP4 모두 `readyState 0`) 실측하지 못했다. 루프 로직 자체는 가상 클럭 단위 테스트로 검증되어 있으나, **실제 미디어로 한 번 확인이 필요하다.**

- 텍스트창 확인 완료 — Ctrl+T 열기 → 3번째 줄 수정이 3번 문장 받아쓰기에 반영 → Enter로 다음 문장 재생 → F2 자막 원문
- YouTube 확인 완료 — URL 입력 → 사이드바 안내 → 스크립트 붙여넣기 → 7문장 반영, 타임스탬프 정확
